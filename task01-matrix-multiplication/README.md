# Задача №1: Умножение матриц (обычное и блочное)

## Постановка задачи

Реализовать два способа умножения квадратных матриц:
- **Обычное** — три вложенных цикла (i, j, k).
- **Блочное** — шесть вложенных циклов (три по блокам, три внутри блока).

Провести теоретический анализ и бенчмаркинг. Фокус варианта: **П (память)**.

## Теоретический анализ

### Обычное умножение

Формула: `C[i][j] = Σₖ A[i][k] · B[k][j]`

- **Время:** O(n³) — три вложенных цикла по n.
- **Память:** O(n²) — только результирующая матрица.

### Блочное умножение

Матрицы разрезаются на блоки `b × b`. Формула та же, но элементами выступают блоки:
`C(I,J) = Σₖ A(I,K) · B(K,J)`

- **Время:** O(n³) — операций столько же, сколько у обычного (n³ скалярных умножений).
- **Память:** O(n²) — тоже только результат.

### От чего ещё зависит время

Помимо размера `n`, время зависит от:
- **Порядка обхода памяти.** В обычном умножении внутренний цикл обращается к `B[k][j]` — это столбец, а матрица в Java хранится по строкам. Отсюда промахи кэша.
- **Размера блока `b`** в блочном умножении — от него зависит, попадает ли рабочее множество в кэш.
- **Размера кэша процессора.**
- **Типа данных** (`double` = 8 байт).

## Фокус «П — память»

### Дополнительная память сверх входных данных
- Обычное умножение: **O(n²)** — только матрица результата.
- Блочное умножение: **O(n²)** — тоже только результат. Дополнительных копий блоков нет.

### Глубина рекурсии
**0** — оба алгоритма итеративные.

### Пиковое потребление
- Вход: `2 · n² · 8` байт (две матрицы `double` n×n).
- Результат: `n² · 8` байт.
- Итого пик: `3 · n² · 8` байт.

Пример для n=2048: `3 · 2048² · 8 ≈ 100 МБ`.

### Счётчик элементов (по требованию задания)
- **Выделено:** n² элементов (результат).
- **Скопировано:** 0.
- **Живо одновременно:** 3n² (вход + результат).

### Что отдано взамен
- Блочное умножение **не экономит память** по сравнению с обычным — у обоих O(n²).
- Выигрыш блочного — в **локальности доступа к кэшу**, а не в памяти.
- На маленьких `n` (меньше размера блока) блочный проигрывает из-за накладных расходов на индексацию блоков — это и есть «размен невыгоден».

## Тесты

Покрытие (unit-тесты, JUnit 5):
- Happy path: 2×2.
- Единичная матрица: A · I = A, I · A = A.
- Краевой случай: 1×1.
- Краевой случай: умножение на нулевую матрицу.

Все тесты проходят.
